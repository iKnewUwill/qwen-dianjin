## 5. 新增：偏好构造方式消融（4 组）

对应 `实验方案.md` 阶段五，控制变量法定位「步骤级 / 轨迹级 / 融合 / 权重调优」各自贡献：

| 实验组 | 步骤级评分 | 轨迹级评分 | 融合方式 | 回答的问题 |
|:---:|:---:|:---:|:---:|------|
| 基线组 | ✗ | ✓ | 无（仅轨迹级） | 旧方案作为对照 |
| 实验组A | ✓ | ✗ | 无（仅步骤平均） | 步骤级单独够不够 |
| 实验组B | ✓ | ✓ | 静态权重 α=0.5 | 融合是否优于单一信号 |
| **完整方案组** | ✓ | ✓ | 加权融合（α, β 调优） | 权重调优是否优于静态 |

为什么是 4 组、而不是最小对照 2 组，详见 §6。

---

## 6. 为什么是 4 次偏好构造方式消融

**4 组通过控制变量拆出三个独立增益来源**：

```
基线组 ──(改信号: 轨迹级→步骤级)──▶ 实验组A     → 回答「步骤级 vs 轨迹级谁更有用」
基数组/A ──(加融合: 单信号→加权)──▶ 实验组B      → 回答「融合是否优于单一信号」
实验组B ──(调权重: 静态→调优)────▶ 完整方案组    → 回答「权重调优是否值得」
```

- 若「完整方案 > 基线」但「A ≈ 基线」，说明增益主要来自**融合**而非步骤级信号本身；
- 若「A > 基线」但「B ≈ A」，说明步骤级信号已足够、融合无额外增益；
- 若「B > A/基线」但「完整 ≈ B」，说明静态 0.5 已够、调优无必要。

每多一组只多一次 DPO 训练（~2.83h），成本可接受，却能避免「新方案好了但不知道为什么好」。这就是 4 组而非 2 组的理由。

## 7. 端到端三维度评估的范围（分层评估）

**不需要对 4 个模型都做三维度评估。** 采用分层策略（延续 `消融实验方案.md` §6.1）：

| 评估层 | 适用对象 | 指标 | 是否调大参数模型 |
|------|------|------|:---:|
| 中间指标 | **4 个消融模型全部** | 偏好准确率 / reward margin（`eval_dpo.py`） | ❌ 本地 |
| 端到端三维度 | **仅关键组** | 过程 / 结论 / 数据引用正确率 | ✅ 235B |

理由：

1. **成本**：三维度评估一次 = DPO 400 题 + BASE 400 题 + 800 次裁判调用；4 个模型全做 ≈ 3200 次调用，成本高且冗余。
2. **目的不同**：偏好构造方式消融的目的只是「选排序方式」，中间指标（偏好准确率、margin）已足以判定哪个排序最好。
3. **三维度评估的目的**是验证「最终 DPO 模型相对基座 / 旧方案的端到端推理提升」，只需对最终选定方案做。

**建议的三维度评估范围**：

- 完整方案（加权融合）vs BASE —— 验证 DPO 端到端相对基座的提升（必做）；
- 完整方案 vs 基线组（仅轨迹级）—— 验证新排序相对旧方案的端到端增益（强烈建议，作为消融结论的端到端佐证）；
- 实验组 A / B —— **不做**三维度评估，中间指标足够。

> 优化：BASE 输出（`test/base/*.json`）对所有 DPO 模型相同，`generate_eval.py --model base` 只需跑一次；各 DPO 模型仅需各自 `--model dpo` 生成后与同一份 BASE 输出对比。

## 8. 执行顺序与依赖

```
[1] 改造 build_dpo_dataset.py：score_answer 一次输出 step_probs + traj_prob，原始分数落盘
        │
        ▼
[2] 一次 PRM 打分（4000 题 × 4 候选 ≈ 16000 次推理，~1h）
        │  缓存原始分数
        ▼
[3] 离线生成 4 种排序的数据集（仅轨迹 / 仅步骤 / 静态 α=0.5 / 加权融合）
        │  7:2:1 拆分
        ▼
[4] 分别训练 4 个 DPO 模型（先跑完整方案，作为 β/epoch 消融的载体）
        │
        ▼
[5] 中间指标评估（eval_dpo.py）—— 4 个模型全做，判定最优排序
        │
        ▼
[6] 在完整方案排序上重做 β 消融（0.01/0.05/0.50，0.10 复用）与 epoch 消融（2/3，1 复用）
        │
        ▼
[7] 端到端三维度评估（仅完整方案 vs BASE + 完整方案 vs 基线）
```

## 9. 工作量估算

| 事项 | 次数 | 单次耗时 | 合计 |
|------|:---:|:---:|:---:|
| PRM 打分（重建数据，1 次缓存复用） | 1 | ~1h | ~1h |
| 偏好构造方式消融（4 组 DPO 训练） | 4 | ~2.83h | ~11.3h |
| β 消融重做（0.01 / 0.05 / 0.50，0.10 = 完整复用） | 3 | ~2.83h | ~8.5h |
| epoch 消融重做（DE-2 / DE-3，DE-1 = 完整复用） | 2 | ~2.83h | ~5.7h |
| 端到端三维度评估（2 组对比） | 1 | 视裁判调用 | 待定 |

**独立 DPO 训练合计 9 次，约 25.5h（单卡串行）**，其中完整方案为核心、被 β/epoch 消融复用，建议优先跑。
