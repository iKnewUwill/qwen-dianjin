# 导师视角质疑与应对方案

> 模拟导师对论文行文、结构、设计、方法、工作量等一切内容的质疑，逐个列举并提出应对方案。
> 本轮已同步论文最新状态，重点新增「源报告与论文数字双轨」「创新点残留旧数字」等行文一致性质疑。

## 一、选题与定位类

### 1. 「三阶段架构」的工作量边界不清
**质疑**：论文自称「三阶段递进训练架构」，但阶段一（PRM）数据合成依赖外部 235B 模型、阶段二（偏好数据）复用外部预生成样本（`dpo_pre.jsonl` 的 4000 题从何而来？）、阶段三（DPO）是标准 TRL 调用。你真正做了什么？「数据合成管道」是论文描述还是真实实现？

**应对**：在「研究内容」中诚实划清「自己实现」与「外部依赖」的边界；说明 `dpo_pre.jsonl` 的生成方式（若为外部生成需注明）；把工作重心如实落在「PRM 训练 + 偏好数据构建 + DPO 对齐 + 三维度评估」这条主线上。

### 2. 「银行金融场景」与实际数据的错位
**质疑**：数据是上市公司财报（Wind/Choice），但论文反复强调「银行业务、信贷审批、风险预警」。财务分析 ≠ 银行信贷，应用场景与数据来源不匹配。

**应对**：要么收紧场景表述为「财务分析辅助决策」，要么补充银行场景数据的论证；避免在摘要里承诺「信贷审批」这种与实验无关的高风险场景。

### 3. 创新点与「工程调参」的区分
**质疑**：三个创新点中，「LoRA 微调」「DPO 对齐」「三 Agent 合成」都是成熟技术，你的增量在哪里？过拟合修复（7ep→5ep）更像调参。

**应对**：重新提炼真正的增量——(1) 步骤级+轨迹级双层 PRM 评分头用于偏好排序；(2) 步骤平均 vs 加权融合的排序方式消融发现「步骤级信号是核心」；(3) 小样本 PRM 过拟合的量化规律。把「用成熟技术」弱化，把「新发现」前置。

## 二、结构行文类

### 4. 章节命名与内容不符
**质疑**：第 4 章标题「基于财务合成数据的过程奖励模型」，但该章大量篇幅是 DPO 数据构建与训练（实验五/六/七）。PRM 和 DPO 是两个模型，为何塞在同一章？

**应对**：要么把第 4 章改为「实验验证」（涵盖 PRM 与 DPO），要么把 DPO 部分拆到独立章节。至少修正标题与内容的对应关系。

### 5. 摘要「0.69」与正文「0.686」不一致
**质疑**：摘要（含英文摘要）写「平均区分度 0.69」，正文三阶段架构与实验五写「0.686」，四舍五入口径不统一；摘要「步骤准确率达 95%」与正文强调的 test 94.00% 也不一致。

**应对**：摘要统一用正文口径（0.686 或明确写 0.69≈0.686）；「95%」改为「94%~95%」或注明 val/test 口径，避免导师逐字对摘要。

### 6. 创新点(3) 残留「96% 以上」旧数字
**质疑**：创新点(3) 写「留出集取得 96% 以上的偏好准确率」，但正文实验六、结论章都写 99.25%/99.50%。同一篇论文内同一指标两个数字，这是硬伤。

**应对**：全文搜索「96%」，把创新点(3) 统一为 99.25%（并区分 val/test），确保摘要、创新点、实验六、结论章四处一致。

### 7. 图表编号与正文引用
**质疑**：正文引用 `\ref{tab:dpo-final-eval}` 等表格，但实验七新增了 4 张表（abl-ranking/abl-beta/abl-epoch/abl-temp/abl-epoch-prm/abl-data），编号是否连贯？图 18/21 在「图表说明」里补了，但正文实验五是否引用了？

**应对**：全文核对图表编号与 `\ref` 引用的一致性，避免「图 XX 不存在」或编号断裂。

### 8. 术语混用（最易被导师挑出）
**质疑**：全文「margin」一词至少两个含义（数据侧 PRM 分数差 0.686、奖励侧隐式奖励差 5.92），「步骤准确率」既指 PRM 判别（95%）又隐含指 DPO 生成（61%），「步骤平均」既是消融组名又是核心方法。术语不统一是硬伤。

**应对**：论文已新增「数据 margin / 奖励 margin / PRM 判别准确率 / 策略步骤正确率」术语表（§5.3.3），需确认该术语表在正文所有出现处都被遵守；「步骤平均」统一写「仅步骤平均排序」。

### 9. 源报告与论文「数字双轨」（本轮新增，最严重）
**质疑**：论文正文已切到「步骤平均」重做口径（99.25%/99.50%、β 0.94~11.21、epoch 5.73~8.44），但 `DPO评估报告.md`、`实验方案.md`、`消融实验结果.md`（DPO 部分）、`ablation_logs/results_summary.md` 仍写旧「纯轨迹级」口径（96.88%/96.00%、0.88~8.33、5.0~6.94）。你的技术报告和你的论文对不上，导师/答辩委员翻报告一问就穿帮。

**应对**：立即更新 `DPO评估报告.md` §4（96.88%→99.25%）、`实验方案.md` §4.2、`消融实验结果.md` §3（β/epoch 换重做数值）三处；`ablation_logs/results_summary.md` 标注「旧口径已作废，见 DPO重做执行记录.md」。这是零成本的文档同步，但决定论文可信度。

### 10. 温度 T=2.0 表述前后矛盾
**质疑**：消融实验证明「打分温度 T 对分类结果无影响」，但 `DPO样本构建过程.md` §4.3 仍写「缓解旧版 PRM 过拟合」、`实验方案.md` §2.3 写「温度 T=2.0 平滑解决过拟合」。这个「温度」到底干嘛的？前后矛盾。

**应对**：统一说明——T 只影响置信度数值（不影响分类阈值决策），数据构建用 T=2.0 是为了压缩概率避免过置信，而非「改善校准/缓解过拟合」；删除「缓解过拟合」这类已被消融证伪的表述。

## 三、实验设计类

### 11. 实验六训练曲线与评估表「跨模型」
**质疑**：实验六的 `tab:dpo-final-steps`（训练曲线，step 170 loss 0.084、margin 5.250）来自旧纯轨迹级 `dpo_v3_4000`，而 `tab:dpo-final-eval`（99.25%/99.50%、margin 5.92/6.20）来自重做 `redo_sm`。两个表不是同一个模型，读者会以为「0.084 的 loss 训练出了 99.25% 的模型」，这是误导。

**应对**：统一实验六为同一模型（建议全部用 `redo_sm`），或明确标注两表来源并给出「训练曲线是轨迹级基线、评估是步骤平均最终模型」的说明。补录 `redo_sm` 的完整训练曲线与评估明细（含 test margin、chosen/rejected 奖励）。

### 12. 缺少对照实验的完整性
**质疑**：DPO 三维度评估只评了 step_mean 和 fusion_weighted 两个模型，没把「旧纯轨迹级模型」纳入端到端对比，无法直接证明「步骤平均排序」在端到端上优于「纯轨迹级」。

**应对**：补跑旧纯轨迹级模型的端到端生成 + 三维度评估（成本低，复用现有 base 输出与裁判流程），补齐「三种排序方式端到端对比」。

### 13. 消融实验的「控制变量」不干净
**质疑**：β 消融和 epoch 消融都跑在「加权融合」排序上，但偏好构造方式消融发现「仅步骤平均」最优。那么在「加权融合」上做的 β/epoch 消融，结论能否推广到最优的「步骤平均」？

**应对**：说明 β/epoch 消融结论（margin 随 β 单调、epoch 单调微升）是**方法无关的通用规律**；或在局限性中声明「β/epoch 消融基于加权融合排序完成，未在步骤平均排序上重复」。

### 14. 三维度评估的裁判随机性未控制
**质疑**：base 模型在两个结果文件中结论满分率差 3.75pp（46.00% vs 49.75%），说明裁判有显著随机性。在此噪声下，「步骤正确率 -1.47pp」这种小差异完全不可信，「结论正确率 +11.75pp」勉强可信。评估可靠性论证缺失。

**应对**：补做「裁判一致性校验」——对同一批样本重复裁判 N 次，报告一致性；或对关键结论给出「噪声界」的量化说明（已估算 ±2~4pp）。

## 四、方法严谨性类

### 15. 数据侧 margin 与奖励侧 margin 混淆
**质疑**：实验五说 margin 0.686（数据侧），实验六说 margin ~5.9（奖励侧），数值量级差 10 倍却都用「margin」一词，读者极易混淆。

**应对**：全文统一「数据 margin」与「奖励 margin」两个术语（论文术语表已加，需全文遵守）。

### 16. 评测指标与实验方案的对应
**质疑**：实验方案阶段三列了「推理准确率、推理过程质量、偏好对齐、生成多样性、策略稳定性、参考偏离度」六项，但论文只报告了前三项，「生成多样性」「参考偏离度（KL）」完全没提。

**应对**：要么补测（KL 可用 `eval_dpo.py` 快速算、多样性可重生成统计），要么在局限性中明确「未评估」并说明原因。

### 17. 端到端评估「数据引用」维度自创但未定义清楚
**质疑**：「数据引用准确性」这个维度是自创的，论文没有给出严格的操作化定义（什么算「引用准确」？），裁判 prompt 里的标准是否可复现？

**应对**：在论文中给出三维度（结论/步骤/数据引用）的明确评分 rubric 与裁判 prompt 原文（或附录），确保可复现。`235B评估方案.md` 已有裁判 prompt，可提炼进论文附录。

## 五、工作量与深度类

### 18. 全文「未来工作」与「已完成」的自洽
**质疑**：论文「未来工作」之前写「235B 外部评估」「消融实验」，现在都已做完（三维度评估、11 组消融），未来工作已改写，但全文其他角落（`实验方案.md`「待评估」、`消融实验方案.md`「待跑」、`DPO评估报告.md` §8「待评估」）仍残留「待做」表述，自相矛盾。

**应对**：全局搜索「待评估」「待跑」「未来将」「计划」等关键词，源报告统一为「已完成」或标注「已废弃」；论文正文只需保证未来工作与已完成实验一致。

### 19. 消融源报告陈旧，与论文消融章节不符
**质疑**：论文实验七的 β/epoch 消融用的是重做新数值，但 `消融实验结果.md` §3 和 `ablation_logs/results_summary.md` 还是旧数值（96.88%/96.00%、0.88~8.33、5.0~6.94）。答辩时若被要求「把消融原始数据拿出来」，新旧对不上。

**应对**：`消融实验结果.md` 的 DPO 部分（§3.1/§3.2/§四.D/§四.E）整体替换为重做数值，并保留旧值标注为「旧口径基线（已作废）」；`results_summary.md` 头部加一行「DPO β/epoch 已按步骤平均/加权融合重做，见 DPO重做执行记录.md」。
