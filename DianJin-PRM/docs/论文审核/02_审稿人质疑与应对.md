# 审稿人视角质疑与应对方案

> 模拟一位严格审稿人对论文每一个结论的质疑。每个质疑标注严重等级（🔴致命 / 🟠严重 / 🟡中等 / 🟢轻微），并给出应对方案。
> 本轮核查已同步论文最新状态（2026-10-13），重点新增「报告双轨」与「实验六跨模型」两类新质疑。

---

## 结论一：PRM 步骤准确率 94–95%，实现步骤级过程监督

**🔴 质疑**：你的「步骤准确率」是「PRM 判断步骤对错」的准确率，不是「策略模型生成步骤」的正确率。你把「裁判准确」包装成了「过程监督有效」，但过程监督的价值在于**让策略模型变好**。端到端评估（步骤正确率 61.51% vs 62.98%）恰恰说明策略模型的步骤质量没有提升，甚至略降。那么「步骤级过程监督」这个核心卖点，究竟产生了什么可观测的收益？

**应对**：明确区分「PRM 判别能力」（95%）与「策略模型生成质量」（~61%）两层指标；把 PRM 定位从「直接提升策略」改为「提供偏好信号的打分器」；在摘要/结论如实说明「95% 指判别能力，其价值体现为构建高区分度偏好数据，而非直接提升策略步骤质量」。

---

## 结论二：小样本过拟合修复（7ep→5ep，错误召回 0.9%→79.5%）

**🟠 质疑**：这个发现本质是「训练设置错误（7 epoch 过拟合）被纠正」，「修复了一个自己引入的 bug」能否算创新点？审稿人可能认为这是工程调参，不是科学贡献。

**应对**：将表述从「创新」降级为「重要经验教训」；强调小样本 PRM 过拟合（错误召回崩溃、置信度饱和）是一个**有普遍性的现象**，而非本项目独有的失误；用三组消融（epoch 3/5/7、数据规模 500/1000/1995）证明这是系统性的「小样本过拟合」规律，而非孤例调参。

---

## 结论三：DPO 偏好数据 margin 0.686，高质量

**🟠 质疑**：0.686 这个 margin 是「纯轨迹级 prob_1 排序」得到的数据，但你的最终方法（实验七消融）却证明「仅步骤平均」最优（99.25%），加权融合次之。那么实验五宣称的「0.686 高质量偏好数据」到底是哪种排序构建的？0.686 和最终使用的「步骤平均」数据是什么关系？

**应对**：这是新出现的口径风险。策略：(1) 在实验五明确说明 0.686 是「轨迹级排序」的规模化构建结果，其价值在于证明「PRM 修复过拟合后能产生高区分度偏好信号」；(2) 实验七进一步证明「步骤平均排序」在偏好准确率上更优（99.25% vs 96.88%），最终模型采用步骤平均；(3) 补一张「三种排序方式下的数据 margin 对比表」（轨迹级 0.686 / 步骤平均 / 加权融合），消除口径混淆，避免审稿人质疑「0.686 和最终方法对不上」。

---

## 结论四：DPO 训练收敛，偏好准确率 99.25%

**🔴 质疑（新增，当前最致命）**：99.25%/99.50% 这个数，在你自己的 `DPO评估报告.md` 里查不到——那里写的是 96.88%/96.00%。你的实验六正文用了 99.25%，但训练曲线表（`tab:dpo-final-steps`）的 step 170 loss 0.084、margin 5.250 却来自另一个模型（旧纯轨迹级）。**你实验六里的「训练过程」和「留出集评估」是同一个模型吗？如果不是，你的 99.25% 从哪来？**

**应对**：这是必须正面回应的致命质疑。策略：(1) 立即在 `DPO评估报告.md` / `消融实验结果.md` 中补录「步骤平均」重做模型（`redo_sm_b0.1_e1`）的完整评估结果（val/test 准确率、margin、chosen/rejected 奖励），使 99.25% 有可查来源；(2) 统一实验六的训练曲线与评估表为同一模型，或明确标注「训练曲线来自轨迹级基线、评估来自步骤平均最终模型」并给出理由；(3) 在全篇报告、附录中保证「99.25%」只对应 `redo_sm` 一个模型，杜绝双轨并存。

## 结论五：偏好准确率 99.25% 是自指指标

**🔴 质疑**：99.25% 的「偏好准确率」衡量的是「隐式奖励 chosen > rejected」的比例，这是**自指指标**——数据由 PRM 打分排序，模型又去拟合这个排序，高准确率只能说明「模型学会了复现 PRM 的偏好」，不能说明「模型更会推理」。它与「真实答案正确率」没有必然关系。

**应对**：这是最关键的概念质疑。必须用**端到端三维度评估**（结论正确率 +11.75pp）证明「偏好对齐确实带来真实推理提升」，并把偏好准确率明确定位为「对齐程度指标」而非「能力指标」。同时承认：偏好准确率 99% 的边际价值有限，真正有说服力的是端到端 +11.75pp（相对 +25.5%）。

---

## 结论六：偏好构造方式消融——仅步骤平均最优

**🟡 质疑**：四组排序方式的偏好准确率差异（96.88% → 99.25%）只有 2.4 个百分点，且四组都远超 70% 目标。这么小的差异，「仅步骤平均最优」是否有统计显著性？是否只是随机波动（尤其你单次运行、无多 seed）？

**应对**：报告每组模型是单次运行；把结论表述从「显著最优」弱化为「在本次实验中表现最好，差异在 2.4pp 之间」；若成本允许，补一次多 seed 验证；至少说明「步骤平均 ≥ 加权融合 ≥ 静态 ≥ 轨迹级」的排序在 val/test 双口径上一致，方向稳健。

---

## 结论七：端到端结论正确率 +11.75pp

**🟠 质疑**：结论正确率从 46.00% 到 57.75%，绝对正确率**不到 60%**。一个正确率只有 57.75% 的财务分析系统，离「面向银行业务、信贷审批」的应用目标差得很远。+11.75pp 的相对提升（25.5%）掩盖了绝对水平的不足。

**应对**：如实定位研究阶段——这是「相对提升」的可行性验证，而非「达到生产可用」；摘要/结论同时给出绝对值（57.75%）与相对提升（+25.5%），不回避绝对水平；把「信贷审批等核心场景」措辞改为「提供辅助决策支持」等保守表述。

---

## 结论八：步骤正确率持平、数据引用略降

**🔴 质疑**：这是论文最大的软肋。三维度评估显示「步骤正确率 -1.47pp」「数据引用 -4.25pp」，即 DPO 在**两个维度上反而变差**。这直接挑战「PRM+DPO 实现精细过程监督优化」的核心主张。审稿人会问：你的方法到底优化了什么？只是让模型更自信地给出同样的答案？

**应对**：(1) 诚实承认 DPO 收益集中在「结论正确性」，未传导到「步骤过程」与「数据引用」；(2) 把「步骤过程质量提升」从核心结论移除，降级为「局限性 + 未来工作」；(3) 用「偏好对齐优化的是整体答案正确性，而非逐步骤过程」解释机制；(4) 明确数据引用是共性短板（base 也仅 35%），不是 DPO 引入的退化。

## 结论九：三维度评估的裁判是 qwen3.8-flash，非 235B

**🟠 质疑**：论文结论章写「大参数模型（qwen3.8-flash）」，但 `qwen3.8-flash` 是一个轻量 flash 模型，不是「大参数模型」。用小模型当裁判，评估权威性存疑；且「大参数模型」这一措辞有误导之嫌（`235B评估方案.md` 仍写「裁判：大参数模型（235B）」）。

**应对**：统一全文措辞，删除「大参数」定性，直接写「裁判模型 qwen3.8-flash（batch API 调用）」；论证「结构化三维度评判（结论/步骤/数据引用各 0/0.5/1 打分）对裁判规模不敏感」；补做「裁判一致性校验」（同一批样本多次裁判的一致性），证明裁判结果可靠，尤其因为 base 两文件结论满分率已差 3.75pp。

## 结论十：数据是 LLM 合成的，ground truth 可靠性存疑

**🟠 质疑**：1,995 条 PRM 训练数据由「Proposer→Solver→Validator 三 Agent 管道」合成，其步骤标签是 LLM 生成的。你的 PRM 94% 准确率是「与 LLM 标签一致」，如果 LLM 标签本身有噪声，这个准确率是有偏的。

**应对**：补充「人工抽检」或「双重验证一致性」的量化数据；论文已提 Validator 双重验证，但需给出「一致性比例」的量化数据；如无该数据，列为局限性。注意：`消融实验方案.md` §4.5 已承认「三维度独立分数未落盘」，标签质量回溯受限，需一并说明。

## 结论十二：单卡、小样本、单次运行、且源报告口径双轨

**🟡 质疑（新增）**：全部实验单卡完成，PRM 仅 1,995 样本、DPO 仅 2,800 对，关键结果（偏好准确率、三维度评估）均为单次运行；更严重的是，你的论文和你的技术报告之间存在**数字口径双轨**——报告写 96.88%，论文写 99.25%，让人无法判断哪个才是真实结果。这直接损害论文的「可复现性」与「可信度」。

**应对**：报告随机种子与可复现性说明；对关键结论（步骤平均最优、+11.75pp）补充多 seed 或说明局限；**立即同步所有源报告到新口径**，消除双轨，让每个论文数字都能在报告中找到唯一出处。
