## 实验 13：生成 400 份纯轨迹级样本

**目标**：为 `redo_traj_b0.1_e1`（仅轨迹级）生成端到端评估输出，供后续人工三维度裁判使用。

**命令**（环境 `dianjin-dpo`，约 1.5h）：

```bash
export HF_HOME=/root/autodl-tmp/huggingface
export TRANSFORMERS_CACHE=/root/autodl-tmp/huggingface
export HUGGINGFACE_HUB_CACHE=/root/autodl-tmp/huggingface
export OMP_NUM_THREADS=1

CUDA_VISIBLE_DEVICES=0 /root/autodl-tmp/miniconda3/envs/dianjin-dpo/bin/python \
  src/data_dpo/generate_eval.py \
  --model dpo --lora /root/autodl-tmp/dpo_checkpoint/redo_traj_b0.1_e1 \
  --out_dir src/data_dpo/test/dpo_traj \
  2>&1 | tee src/data_dpo/logs/gen_dpo_traj.log
```

**校验**：`src/data_dpo/test/dpo_traj/` 下应有 400 个 JSON 文件，每个含 `generation.分析过程` 与 `generation.分析结论`，`id` 覆盖 0–399。

**产出**：400 份纯轨迹样本，与已有 base/step_mean/fusion 输出同格式，可直接交人工裁判。

## 实验 15：KL 偏离度补测

**目标**：扩展 `eval_dpo.py` 输出 KL(π_θ‖π_ref)，报告最终模型（redo_sm）的参考偏离度。

**改动**（`src/data_dpo/eval_dpo.py`，约 0.5h）：
1. `logprob_of_response` 改为返回 `(sum, n_tokens)`。
2. `evaluate` 累计并输出四种 KL：`kl_chosen/rejected_per_seq`（=`reward/β`）、`kl_chosen/rejected_per_token`（除以响应 token 数）。

**命令**（约 1h）：

```bash
CUDA_VISIBLE_DEVICES=0 /root/autodl-tmp/miniconda3/envs/dianjin-dpo/bin/python \
  src/data_dpo/eval_dpo.py \
  --lora /root/autodl-tmp/dpo_checkpoint/redo_sm_b0.1_e1 \
  --beta 0.1 \
  --output /root/autodl-tmp/redo_sm_eval_results.json
```

可选：对 β 消融四组（0.01/0.05/0.10/0.50）各跑一次，补全「各 β 的 KL」缺口。

**产出**：KL 数值（每序列 + 每 token 两口径），顺带落盘 redo_sm 的 test margin/chosen 奖励，补齐第 18 项来源链。
