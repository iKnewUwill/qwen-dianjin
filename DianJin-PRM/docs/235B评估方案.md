# 大参数模型外部评估方案（三维度比较）

> 评估对象: DPO 训练后模型 vs 基座 Qwen3-8B | 评估数据: `src/data_dpo/test/dpo_test.jsonl` (400 条) | 裁判: 大参数模型（235B）

---

## 1. 评估目标

对基座模型（BASE）与 DPO 模型在测试集上的生成结果进行盲评，从 **过程、结论、数据引用** 三个维度量化 DPO 训练带来的真实推理提升：

- **过程**：推理步骤的逻辑正确性（步骤级）
- **结论**：最终答案的正确性
- **数据引用**：对已知财务数据（knowledge_items）使用是否准确、充分

> 测试集题目为开放式金融财务分析题（无标准答案），故由大参数模型基于题目与已知财务数据独立评判，而非字符串比对。本方案**摒弃 235B 双重验证**，改为对每份输出做单次三维度评判。

---

## 2. 评估流程总览

```
dpo_test.jsonl (400 题)
        │  取出 question + knowledge_items
        ▼
   ┌─────────────┐         ┌─────────────┐
   │ 基座 Qwen3-8B │         │ DPO 模型     │
   │ (base)      │         │ (base+LoRA) │
   └──────┬──────┘         └──────┬──────┘
          │ 各生成 400 份            │
          │ {steps, final_answer}   │
          ▼                        ▼
   ┌─────────────────────────────────┐
   │ 打乱顺序 + 去除模型标识（盲评）        │
   └───────────────┬─────────────────┘
                    ▼
            大参数模型（235B）三维度评判
            ├─ 过程（步骤逻辑正确性）
            ├─ 结论（最终答案正确性）
            └─ 数据引用（财务数据使用准确性）
                    ▼
            汇总三维度指标，对比 DPO vs 基座
```

---

## 3. 模型生成格式约定

两个模型对每个 `question` 生成时，统一要求按以下格式输出，便于切分步骤、逐步骤评判：

```text
步骤1: <该步骤的推理过程>
步骤2: <该步骤的推理过程>
步骤3: <该步骤的推理过程>
最终结论: <final_answer>
```

- 生成时 prompt 附带 `question` 与 `knowledge_items`（作为已知条件）
- `knowledge_items` 中值为 `None` 的项需**过滤后再拼接**（与数据构建时的处理一致）
- 基座与 DPO 使用**完全相同的生成参数**，保证差异仅来自模型权重

---

## 4. 评价指标体系

对每条样本，大参数模型分别输出三个维度的评分，据此汇总对比指标：

| 维度 | 指标 | 定义 | 目标 |
|------|------|------|------|
| **过程** | 步骤正确率 | 所有推理步骤中判「正确」的比例 | DPO 比基座高 **15% 以上** |
| **结论** | 结论正确率 | 最终结论判「正确」的比例 | DPO 比基座高 **10%–15%** |
| **数据引用** | 数据引用准确率 | 财务数据使用无事实性错误的比例 | DPO 优于基座 |

---

## 5. 三维度评判提示词模板

```text
你是一名资深财务分析师，负责从三个维度评判一份财务分析回答的质量。

【题目】
{question}

【已知财务数据】
{knowledge_items}

【该回答的推理步骤】
{steps 按 "步骤1: ...\n步骤2: ..." 拼接}

【该回答的最终结论】
{final_answer}

请基于题目和已知数据，从以下三个维度独立评判：

1. 过程（步骤逻辑正确性）：每个推理步骤的计算、逻辑推理是否正确，中间结论是否成立
2. 结论（最终答案正确性）：最终结论是否准确、是否抓住问题核心
3. 数据引用（财务数据使用准确性）：是否正确、准确地引用了已知财务数据，是否存在数据误读、张冠李戴或遗漏关键数据

每个维度评分标准：
- 过程：1（正确）/ 0（错误）
- 结论：1（正确）/ 0.5（部分正确）/ 0（错误）
- 数据引用：1（准确）/ 0（存在错误）

只输出 JSON，不要任何其他文字：
{
  "过程": {"score": 0 或 1, "reason": "一句话"},
  "结论": {"score": 0 或 0.5 或 1, "reason": "一句话"},
  "数据引用": {"score": 0 或 1, "reason": "一句话"}
}
```

---

## 6. 执行细节

### 6.1 盲评去偏

将基座与 DPO 的 400 + 400 份输出**混在一起、打乱顺序、去除模型标识**后统一提交评判，避免裁判受「哪个是训练后模型」的心理暗示影响。

### 6.2 成本控制

每条样本仅调用一次大参数模型，一次返回过程/结论/数据引用三个维度的评分（共 800 次调用）。不再对同一输出做双重验证，以控制调用量。
