# 235B 大模型外部评估方案

> 评估对象: DPO 训练后模型 vs 基座 Qwen3-8B | 评估数据: `src/data_dpo/test/dpo_test.jsonl` (400 条) | 裁判: 235B 大模型

---

## 1. 评估目标

DPO 训练报告中的「偏好对齐程度」已完成（held-out 偏好准确率 96.9%），但「推理准确率」「推理过程质量」仍待外部评估。本方案使用 235B 大模型作为裁判，对基座模型与 DPO 模型在测试集上的**生成结果**进行盲评，量化 DPO 训练带来的真实推理提升。

- **推理准确率**：最终结论正确率，DPO 相对基座应提升 10%–15%
- **推理过程质量**：步骤级正确率，DPO 相对基座应提升 15% 以上

> 测试集题目为开放式金融财务分析题（无标准答案），故必须由 235B 大模型基于题目与已知财务数据独立评判，而非字符串比对。

---

## 2. 评估流程总览

```
dpo_test.jsonl (400 题)
        │  取出 question + knowledge_items
        ▼
   ┌─────────────┐         ┌─────────────┐
   │ 基座 Qwen3-8B │         │ DPO 模型     │
   │ (base)      │         │ (base+LoRA) │
   └──────┬──────┘         └──────┬──────┘
          │ 各生成 400 份            │
          │ {steps, final_answer}   │
          ▼                        ▼
   ┌─────────────────────────────────┐
   │ 打乱顺序 + 去除模型标识（盲评）        │
   └───────────────┬─────────────────┘
                   ▼
           235B 大模型评判
           ├─ Prompt A: 结论正确性（三档）
           └─ Prompt B: 步骤正确性（0/1）
                   ▼
          汇总四项指标，对比 DPO vs 基座
```

---

## 3. 模型生成格式约定

两个模型对每个 `question` 生成时，统一要求按以下格式输出，便于切分步骤、逐步骤评判：

```text
步骤1: <该步骤的推理过程>
步骤2: <该步骤的推理过程>
步骤3: <该步骤的推理过程>
最终结论: <final_answer>
```

- 生成时 prompt 附带 `question` 与 `knowledge_items`（作为已知条件）
- `knowledge_items` 中值为 `None` 的项需**过滤后再拼接**（与数据构建时的处理一致，避免污染输入）
- 基座与 DPO 使用**完全相同的生成参数**（采样温度、max_new_tokens、prompt 模板），保证差异仅来自模型权重

---

## 4. 评价指标体系

对每条样本，235B 分别输出结论分（1/0.5/0）与步骤分（0/1），据此汇总四项指标：

| 指标 | 定义 | 公式 | 目标 |
|------|------|------|------|
| **结论正确率** | 最终结论被判「正确(1)」的比例 | 得分=1 的样本数 ÷ 总样本数 | DPO 比基座高 **10%–15%** |
| **平均结论分** | 结论三档分的均值 | Σ(结论分) ÷ 总样本数 | DPO > 基座 |
| **步骤正确率** | 所有步骤中判「正确(1)」的比例 | Σ(正确步骤) ÷ Σ(全部步骤) | DPO 比基座高 **15% 以上** |
| **双重验证一致性** | 同一结论两次独立判断一致的比例 | 一致样本数 ÷ 总样本数 | > 90%（评估自身可靠性） |

## 5. 235B 提示词模板

### 5.1 Prompt A —— 最终结论评判（三档）

```text
你是一名资深财务分析师，负责评判一份财务分析回答的最终结论是否正确。

【题目】
{question}

【已知财务数据】
{knowledge_items}

【该回答的推理过程】
{steps 按 "步骤1: ...\n步骤2: ..." 拼接}

【该回答的最终结论】
{final_answer}

请基于题目和已知数据，独立判断该【最终结论】是否正确、是否抓住问题核心。
评分标准（三档）：
- 1（正确）：结论准确，关键财务事实抓取正确，逻辑和数据支撑充分，无事实性错误
- 0.5（部分正确）：结论方向基本正确，但遗漏关键点、存在数据误用或推理瑕疵
- 0（错误）：结论错误，与已知数据明显矛盾，或答非所问

只输出 JSON，不要任何其他文字：
{"score": 0 或 0.5 或 1, "reason": "一句话说明判分依据"}
```

### 5.2 Prompt B —— 步骤级评判（0/1）

```text
你是一名资深财务分析师，负责逐步骤评判一份财务分析回答的推理过程是否正确。

【题目】
{question}

【已知财务数据】
{knowledge_items}

【待评回答的推理步骤】
步骤1: ...
步骤2: ...
步骤3: ...

请对每一个步骤单独判断其推理是否正确。评分标准：
- 1（正确）：该步骤的计算、数据引用、逻辑推理均正确，中间结论成立
- 0（错误）：该步骤存在计算错误、数据误读、逻辑跳跃，或中间结论不成立

只输出 JSON，不要任何其他文字：
{"steps": [{"step": "步骤1", "score": 0 或 1, "reason": "一句话"}, ...]}
```

---

## 6. 执行细节

### 6.1 双重验证（压降单次判断噪声）

对 Prompt A 的同一份 `final_answer`，用不同采样参数独立判断两次：

- 第 1 次：`temperature = 0`（确定性）
- 第 2 次：`temperature = 0.7`（加扰动）

两次 `score` 一致才采纳；不一致的样本标记为「待人工复核」，不纳入指标（或单独统计其占比，即「双重验证一致性」）。

### 6.2 盲评去偏

将基座与 DPO 的 400 + 400 份输出**混在一起、打乱顺序、去除模型标识**后统一提交评判，避免裁判受「哪个是训练后模型」的心理暗示影响而导致分数虚高。

### 6.3 成本控制

- 步骤评判（Prompt B）对每条样本仅调用一次（一次评完所有步骤，返回数组），不做双重验证，以控制调用量
- 双重验证仅用于结论评判（Prompt A），400 条 × 2 次 = 800 次调用
